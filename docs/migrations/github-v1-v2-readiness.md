# GitHub v1 to v2 migration readiness

## Why this belongs in Atlassian
The migration decision is not only a GitHub code question. Reviewers need Jira work item coverage, support notes, and repository activity in one place before asking a customer to move from v1 to v2.

## Example Atlassian-shaped question
"What GitHub v1 to v2 migration work still needs follow-up for the TPTL project?"

## Signals to combine
- Jira project key: `TPTL`
- GitHub org: `org-beaconstone`
- linked Jira work items
- unlinked pull requests that may not appear in Jira
- support note confirming the customer migration path

## Current follow-up
Beaconstone has linked work items for the core migration plan, but unlinked pull requests still need review before the support handoff is complete.
